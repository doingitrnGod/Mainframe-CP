# External Examiner Demonstration Script

**Title**: External Examiner Demonstration Script - Centralized University Admission System
**Estimated Time**: 15-20 Minutes

## 1. Project Overview (2 min)
- **Objective**: Welcome the examiner. State the objective: to demonstrate a fully functional batch processing pipeline mimicking the Maharashtra State Centralized Admission Process (CAP) using Mainframe technologies.
- **Scope**: Highlight that the system handles everything from raw application validation, deduplication, merit list generation, three rounds of category-based allocation (including Freeze/Betterment/Reject workflows), to fee processing and final academic result evaluation.

## 2. Architecture Walkthrough (2 min)
- Show the directory structure (`JCL/`, `COBOL/`, `DATA/`, `OUTPUT/`).
- Explain the flow: Data Validation -> Sort/Dedup -> 3 Iterations of CAP Allocation with intermediate Acceptance Processing -> Fee matching -> Academic Evaluation.
- Mention that `MASTER.jcl` strings all these independent steps together using Condition Codes (`COND=`).

## 3. Data Files Overview (3 min)
- Open `DATA/APPRAW.dat` and `DATA/SEATMAT.dat`.
- Explain the LRECL (200 for apps, 200 for seats) and point out key fields using column positions (e.g., "Here is the CET score at position 45, and the category at position 48").
- Open `DATA/PREFRAW.dat` to show how students map to multiple college choices.

## 4. Step-by-Step Execution

### a. Show Raw Data with Duplicates
- Open `APPRAW.dat`. Point out intentionally duplicated `STUDENT-ID`s (e.g., ST000099 appears twice) and invalid records (e.g., eligibility 'N' or letters in CET score).

### b. Run STEP01 - Validation + Dedup
- Execute `STEP01.jcl`.
- Show that DFSORT and `APPVALID.cbl` successfully ran.

### c. Show Rejected Records & Dedup Result
- Open `OUTPUT/REJECTS.dat`. Show how the invalid records were caught (e.g., `INV-SCORE`, `NOT-ELIG`).
- Open `OUTPUT/APPVALID.dat`. Show that only one instance of ST000099 remains (the one with the lower APP-ID).

### d. Run STEP02 - Merit List Generation
- Execute `STEP02.jcl`.
- Open `OUTPUT/MERIT.dat`. Show that records are now perfectly sorted by CET Score descending, and ties are broken by ascending Student ID.

### e. Show Seat Matrix
- Open `DATA/SEATMAT.dat`. Note the available seats for categories like OPEN, SC, ST.

### f. Run STEP03 - CAP Round 1 Allotment
- Execute `STEP03.jcl`.
- Open `OUTPUT/ALLOTR1.dat`.

### g. Show Specific Candidates (R1)
- **ST000001 (Top Scorer)**: Show that they received their first preference (`ALLOT-PREF` = 01).
- **ST000047 (ST Category, Unallotted)**: Show this student. They have ST category, but their preferred colleges have 0 ST seats. Thus, `ALLOT-STATUS` is `UNALLOTTED`.

### h. Show Acceptance Decisions
- Open `DATA/ACCEPTR1.dat`.
- Point out **ST000001** (F - Freeze), **ST000010** (B - Betterment), and **ST000012** (R - Reject).

### i. Run STEP04 - CAP Round 2 (Betterment Highlight)
- Execute `STEP04.jcl`.
- Open `OUTPUT/ALLOTR2.dat`.
- Find **ST000010**. In Round 1, they had preference 03. Show that in Round 2, they successfully secured preference 01 or 02 (Betterment successful).
- Find **ST000025**. Show they were `UNALLOTTED` in R1, but picked up a seat in R2 due to others rejecting.

### j. Run STEP05 - CAP Round 3 (Final)
- Execute `STEP05.jcl`.
- Open `OUTPUT/ALLOTR3.dat`. Show final stabilized allotments.

### k. Run STEP06 - Fee Processing
- Execute `STEP06.jcl`.
- Open `OUTPUT/FEEFINAL.dat`. Show `TOTAL-FEE`, `AMOUNT-PAID`, and `PAY-STATUS` (`PAID` or `PENDING`).

### l. Run STEP07 - Academic Results
- Execute `STEP07.jcl`.
- Open `OUTPUT/RESULTS.dat`.

### m. Highlight Edge Cases in Results
- **ST000003**: Show they have good marks, but because their fee is PENDING, their result status is `WITHHELD`.
- **ST000015**: Show they failed the EndSem component, resulting in a `BACKLOG` status.
- **ST000020**: Show their attendance is below 75, resulting immediately in a `FAIL` status.
- **ST000001**: Show a clean `PASS` with an `A` grade.

### n. Final Summary Report
- Execute `STEP08.jcl`.
- Open `OUTPUT/SUMMARY.rpt`. Show the formatted, human-readable statistical breakdown generated by REXX.

## 5. Q&A Talking Points
- Be ready to explain how DFSORT parameters (SORT FIELDS=...) work.
- Be ready to explain how the COBOL table (`OCCURS`) handles the in-memory seat matrix lookup.
- Discuss how batch condition codes prevent later steps from running if early steps abend.
